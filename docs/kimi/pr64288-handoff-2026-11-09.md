## Actual ON/OFF paths

Both arms already use **FP8 latent KV cache and native per-channel FP8 kv_b_proj weights**. The attention flag does not provide an additional persistent weight/cache precision reduction.

| Cached-context stage | OFF | ON, eligible chunk |
| --- | --- | --- |
| Gather / DCP communication | Dequantize latent cache, communicate BF16 | Gather and communicate FP8 bytes |
| Projection | Dynamically quantize BF16 activation; native FP8 linear | AITER fused gather/projection, FP8 operands and FP32 accumulation |
| Expanded K/V output | BF16 | Direct FP8 |
| Cached attention | BF16 Q/K/V AITER FlashAttention | Dynamic FP8 Q plus FP8 K/V FlyDSL FMHA |
| Result contract | BF16 output, natural-log FP32 LSE | Same contract |

Eligibility: maximum query length at least 512 and context length at least 8192.

At a03796b8, any eligible chunk sends the forward into the custom loop. Smaller chunks within that forward then use custom fused projection with BF16 output and BF16 attention. Entire below-threshold forwards use native routing.

The isolated candidate extracts the native gather/project/pack sequence into a common helper and uses it for the smaller mixed-forward chunks. Eligible FP8 operations, thresholds and quantization kernels are unchanged. This isolates a routing difference; it is not a measured optimization.

Uncached native FP8 ASM prefill remains enabled where supported in both arms. New-token portions of cached prefill remain BF16 at the tested PR head. Further new-token FP8 work is deferred.
