# C96 BF16 上下文注意力分析

[English](baseline-kernel-profile.md)

使用 `kimik3-fp4-mi355x-vllm-agentic-mtp`，TP8/DCP8、C96 和固定镜像
`nightly-rocm100-fe4df3df0eb703862c686b256e9fe44fa94c8945`。C96 配方不启用推测解码。
KV 缓存仍为 FP8，专家权重仍为 FP4；`APPLY_FP8CTX=0` 保留原始 BF16 上下文注意力。
一次性的 `[BASELINE-PRECISION]` 日志记录实际 Q/K/V 形状、数据类型和缩放系数，
不会替换注意力调用。

配方在服务器启动 3300 秒后采集 60 秒的 `rocprofv3 --kernel-trace --stats`。
运行时设置回放时长为 1500 秒、warmup=1。解读统计前，必须核实采集窗口与正式回放重叠。
退出时从叶节点到根节点向已记录的子进程发送终止信号，随后最多等待 1200 秒以生成输出，
再执行有时限的清理。该退出修复仍需运行验证。

下载 `agentic_*` 原始产物和 `server_logs_*`。内核 CSV 必须存在、包含 GPU 调度记录，
并覆盖请求的时间窗口。报告完整内核名称、调用次数、总时长、平均值、最小值、最大值、
标准差，以及可用的设备、进程和启动网格信息。只用有效记录计算时长占比；
GPU 时长之和不等于实际经过时间。排除反向或异常时间戳，避免污染百分比。

输入探针提供实际张量精度。内核名称可能包含输入、输出或累加类型，推断必须明确标注。
不能仅根据 BF16 输入断言 softmax 精度；必要时应检查固定版本的 AITER 实现。
