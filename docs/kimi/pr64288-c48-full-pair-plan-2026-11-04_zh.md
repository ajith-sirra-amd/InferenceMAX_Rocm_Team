## 执行顺序

1. **先完成小型评审修改。** 重新读取最新 PR 提交和评论，将两个无关的同步修改
   从 attention PR 拆出，保留 uncached prefill 的现有 ASM 路径，并处理其余简单
   清理意见。8a55b8eac 中四项小型清理已提交，无需重复。
   按用户此前要求，环境变量讨论保持开放。
2. **处理缓存 scale 的准确率问题。** 确认 ATOM 的实际行为，添加有意义的 cached
   outlier/saturation 测试，并在最终性能测试前完成必要修正。
   不随意引入新的缩放数学公式，也不放宽验收条件。
3. **进行定向验证和短性能检查。** 每批代码修改后运行静态检查，再做 GPU kernel
   数值测试，以及评审要求的、与 main 和关闭开关匹配的 vllm bench serve 测试，
   包括低于 FP8 路由阈值的小工作负载。修复这些检查发现的问题。
4. **验证模型准确率。** 在修改后的代码上运行 GSM8K 和长上下文测试，使用正常
   路由并证明优化后的 cached 路径实际执行。旧提交的 GSM8K 结果只能作为历史证据。
5. **冻结最终实现。** 完成代码清理和适用检查，核对评审回复与证据，固定最终源码
   提交并确认镜像和运行时兼容性。AI agent 不请求或添加上游 CI 授权标签；
   外部条件阻塞的检查应明确标为待完成，不能标为通过。
6. **最后运行完整对照。** 前五步完成后，按确认的并发值与 MTP，先运行 FP8 OFF，
   再运行 FP8 ON。两组使用相同的最终提交、镜像、权重、CCD 绑定、TP/DCP 和工作负载，
   仅改变原生 FP8 开关。保留标准完整预热，每组测量 3600 秒。
7. **发布最终证据。** 检查完整日志、请求错误、coverage、延迟、吞吐及八 rank 执行
   证明，再更新 PR 的结果和版本范围。这一步只更新报告，不修改实现。
   若完整对照后仍需功能修复，应返回验证阶段，并在共同的最终版本上重跑受影响的对照。

完整 OFF/ON 对照是本 PR 工作最后的 GPU 性能阶段。
