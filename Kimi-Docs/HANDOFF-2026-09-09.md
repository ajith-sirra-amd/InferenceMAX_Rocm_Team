## The thing that dominated this slot

**`kernel.numa_balancing` was 1.** The node rebooted ~16 h ago — between T288
(fine) and T289 (first slow run) — and the setting reverts to 1 on every reboot
because the persistent file did not exist.

With a **~1.8 TB host offload pool** (226.89 GB/rank × 8) under constant
read/write, the kernel migrates that working set continuously. Symptom:

- warmup crawls (T291b: **44/148 in 3 h**; T286 finished 148 in 28 min)
- **GPUs still look busy** (25–96%) — so it does *not* match the T273 stall signature
- workers pinned at **~300–320% CPU**
- zero errors throughout

**Cost: four runs and ~7 h of a 13 h slot.**

**Two mistakes worth not repeating:**

1. I asserted I could not run `sudo` **without testing it**. Passwordless sudo
   *is* available — `sudo -n true` confirms in one second. That false constraint
   turned a one-command fix into a seven-hour block.
2. I reported "blocked on the sysctl" across ~15 polls instead of stopping and
   making the ask the headline once.

Now gated automatically in three places: **preflight gate 4b** (blocks dispatch),
**heartbeat** (alerts every wake), and the **abort rules** (first thing to check
when warmup crawls with GPUs busy and no errors).

**Corrected during this campaign:** extra KV *does* raise GPU prefix-cache hit —
+8.4% KV bought **+6.1 pts** (T286 77.2% → T288 83.3%) over matched
unique-token ranges. I had claimed it "bought nothing"; that was wrong. It simply
could not offset eager decode's −39.5%.

**Rule that came out of T288:** graph decode always, never bother graphing
prefill. Decode paces the pipeline because a trajectory cannot start its next
turn's prefill until the current turn finishes decoding.

**Abort:**

| condition | action |
|---|---|
| warmup crawling, GPUs busy, 0 errors | **check `numa_balancing` first** |
| optimisation run `tput_in` < 60,000/s at +25 min | cancel |
| optimisation run `tput_in` < 92,000/s at +50 min | cancel |
| attribution run slow | let it finish — the number *is* the deliverable |
| warmup flat 10+ min **and GPUs 0%** | stall → cancel, then `docker rm -f bmk-server` |
| run `in_progress` with **no container** and GPUs idle | hung before `Launch job script` → cancel, will not recover |

**Always:** `gh run cancel` does **not** stop the container — `docker ps` after
every cancel. Dispatch resolves the **branch**, so commit+push before dispatching.

**Tooling:** `.claude/preflight.sh <minutes>` (14 gates, binding) ·
`.claude/dispatch.sh <minutes> "<label>"` (only sanctioned start path) ·
`.claude/heartbeat.sh <secs>` (monitor only, never dispatches).
